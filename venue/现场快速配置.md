# 赛场快速配置手册（one-api token 平台 → sapper + pi 本机链路）

> 赛前已验证：整套脚本用 uzip 真值跑通过（2026-11-17）。
> 现场只需拿到三样东西：**平台地址、API Key、模型名**，然后跑一条命令。

---

## 0. 现场从组委会/平台页面拿到

| 需要 | 长什么样 | 常见坑 |
|---|---|---|
| 平台地址 | `http://<ip>:<port>`（one-api 控制台域名或 IP） | —— |
| API Key | `sk-` 开头一长串 | 令牌页新建的"令牌"，不是登录密码 |
| 模型名 | 如 `deepseek-flash` / `deepseek-v4.1-flash` | **必须与平台"模型"页逐字一致，区分大小写** |

---

## 1. 一键接入（sapper + pi 本机链路，推荐主链路）

打开终端，把三个值填进去：

```bash
~/ctf/venue-setup.sh http://<平台IP>:<端口>/v1 sk-xxxxxxxx deepseek-flash
```

地址建议带 `/v1` 后缀（one-api 的 openai 兼容端点）；漏了脚本会自动补试并把补全后的地址写进配置。

脚本自动完成 5 步并自检：
1. 网关快速冒烟（max_tokens=4 最小请求，报错自动分类；**失败不写任何文件**）
2. pi 新增 provider `venue`（不动其它档），模型档写成 `venue/<模型名>` 限定形式
3. 更新 `~/ctf/sapper.env` 模型相关行（`SAPPER_MODEL`/key 池 venue 置顶；**预算、路径、GLM 兜底凭据原样保留**，每次改动自动备份）
4. 冒烟②：pi 直连（要求回复"直连"）
5. 冒烟③：sapper 引擎包装器（要求真实执行 `echo venue-ok`）

五步全 ✓ 即接入完成；任一步 ✗ 按第 5 节排查。恢复默认档（bjp-uzip）：

```bash
~/ctf/venue-setup.sh --restore
```

逐条测 key / 看额度 / 改预算用 **Token 管理台**：桌面「Token 管理台」图标，或 http://127.0.0.1:8790 。

## 2. 开赛作战流程（接入完成后）

```bash
source ~/ctf/sapper.env
sapper-ctf-new <题名> "<目标描述>" [靶标URL]     # web 题带 URL，本地附件题不带
cd ~/data/01code/16CTF/sapper-runs/<题名>

# 本地附件题：先手工种一个起步 intent（reasoner 冷启动更稳）
#   把附件真相（file 识破/结构）用 sapper fact 种进去，再：
#   sapper intent "<第一步做什么>" --from <fact-id> --creator human --confirm

sapper auto --model "$SAPPER_MODEL" --minutes 30 --skip-permissions --verify
```

- `--verify` 必带（防士兵谎报）
- flag 找到会自动 `sapper flag` 记账；**提交仍需手动**（复制 flag 去平台交）
- 断点续跑/换思路重派：`sapper dispatch <intent-id> --claim --model "$SAPPER_MODEL" --skip-permissions`

```bash
cd ~/data/03tools/CTF-BTFly-1.3.1

#   CTF_MODEL_VENUE_FLASH_API_KEY=<key>

curl -s http://127.0.0.1:18731/health           # 应回 {"status":"ok"}
```
GUI（bin/CTF-BTFly）里建题时模型选 venue-flash。

## 5. 排错速查

| 症状 | 原因/处理 |
|---|---|
| 冒烟①失败：connection refused | 地址少了 `/v1`；或端口不通（平台仅内网？确认本机在同一网段） |
| 冒烟①失败：401/无效 key | key 复制不全；或 one-api 令牌未启用/分组不对 |
| 冒烟①失败：model not found | 模型名与平台不一致（大小写/下划线），去平台"模型"页照抄 |
| 冒烟②失败但①通过 | sapper.env 没写 export（本脚本已带 export，勿手工删）；或 ~/.local/bin 不在 PATH |
| auto 报 "`claude` CLI not found" | sapper.env 的 `SAPPER_BIN` 没生效——确认用了 `source` 且每行有 `export` |
| 上游 90 秒掐断长回答 | 已是流式调用，正常不会遇到；若复现把单题 --minutes 调小分多次跑 |
| 引擎一直没回复 | 平台限速/并发限制；把 SAPPER_MINUTES_PER_CHALLENGE 调大，或单题单独跑 |

## 6. 本机环境备忘（现场无需动，仅查证用）

- pi：1.5.2，providers = bjp-uzip(默认档) / cc-switch-deep-seek / cc-switch-codingplan / cc-switch-zhipu-glm(+现场跑完脚本会多个 venue)
- 引擎包装器：`~/.local/bin/sapper-pi-engine`（claude 信封 ↔ pi JSONL）
- 模型档配置：pi `~/.pi/agent/models.json`（key 内嵌 provider）+ `~/ctf/sapper.env`
- sapper 建题目录：`~/data/01code/16CTF/sapper-runs/`
- KB：sapper 自带 `kb/`（260 技法卡，`sapper kb search` 检索只回摘要，不烧 token）——**现场保持启用**
- 离线能力：全链路不需要公网；只需要能连到 one-api 平台地址
